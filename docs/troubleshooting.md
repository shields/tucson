# Troubleshooting

Start with the status page and `/readyz`; use `/healthz` to distinguish a live
process waiting for dependencies from failed coordination. Check JSON logs and
Prometheus metrics for the bounded error code, freshness ages, reconnect count,
queue depth, command outcome, and source revision. Keep raw configuration,
credential files, and TinyTuya objects out of diagnostic output.

| Symptom                                            | Checks and action                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                              |
| -------------------------------------------------- | ---------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- |
| Validation exits nonzero                           | Run `validate-config` with the same mounts or environment as the daemon. Check JSON syntax, duplicate keys, required fields, unique identities/topics, protocol strings, secret references, and UID/GID 65532 read access. Configuration errors omit supplied values.                                                                                                                                                                                                                                                                                                                          |
| Liveness fails or the process exits                | Unexpected application errors and violated worker/shutdown bounds are fatal. Inspect the logged exception type and revision, fix the cause, and restart explicitly. A dependency outage alone should leave liveness healthy.                                                                                                                                                                                                                                                                                                                                                                   |
| MQTT remains disconnected                          | Verify broker DNS/routing/port, credentials, CA/client certificate mounts, TLS verification, MQTT 5 support, and ACLs for all configured topics. Reconnect/failure counters show continued attempts. Qualify granted QoS and subscription options on the deployed broker.                                                                                                                                                                                                                                                                                                                      |
| Controller remains unavailable                     | Verify reserved LAN address, configured port and measured protocol, secret-file access/key, and Wi-Fi. Stop any other bridge that drives the same controller. A device that accepts only one local connection can drop the bridge’s session when `inspect` or another LAN client connects. On macOS, a process without Local Network permission gets “No route to host” for LAN addresses while `ping` still succeeds. Changed pairing requires replacing the key and restarting.                                                                                                              |
| Full-status age grows or mapped fields are invalid | Confirm the controller’s actual firmware and DP map against the acceptance record. A socket alone does not establish usability; fresh full status and the current MQTT session are required. Previous snapshots are diagnostic and do not satisfy readiness.                                                                                                                                                                                                                                                                                                                                   |
| Heat setting changes after a successful command    | Compare reported state with the physical controller. A preheat observed to completion (from off, on either side) ended by returning the side to its stored level with the side still on. The manual’s presence rule lowers every zone’s level above 4 to level 4 an hour after an app activation, until the check button is pressed; a power-on at level 5 written as the bridge sends it lowered side B the same way, and power-off ended the window. A 30-minute timer expired and turned side A off. The bridge reports observed changes and does not restore a desired level periodically. |
| Fault code is nonzero                              | The controller reports a fault bitmap whose bits are unknown; Tuya labels them `e1` through `e13`, and the manual mentions only a flashing light and F1/F2 wire-connection codes. The bridge logs `controller_fault` at error level when a nonzero value is first reported or changes and `controller_fault_cleared` at info level when it returns to zero, publishes `fault_code` in both zone snapshots, and exports `tuya_mqtt_controller_fault_code`, without changing availability. Follow the manual’s reset instructions, then record the value and its cause in the acceptance record. |
| Command is rejected                                | Check the result’s error code, current availability/session, strict payload ranges and combinations, enabled write policy, queue depth, and arrival deadline. Commands must be non-retained QoS 0 publications. A retained or expired request does not reach the controller. `zone_off` means a timer was sent for a side that is off; send it with `power` or `heat_level`.                                                                                                                                                                                                                   |
| Command is unconfirmed                             | The write may have reached the controller. Read fresh reported state and inspect the error code. Do not automatically retry a possibly applied write. A new explicit request needs a new request ID; terminal results are session-bound and cached briefly.                                                                                                                                                                                                                                                                                                                                    |
| State looks old after a restart                    | Require a live bridge heartbeat, matching session ID, controller availability, and fresh reported fields. Retained state alone is insufficient. An empty non-retained `get` request republishes usable current snapshots.                                                                                                                                                                                                                                                                                                                                                                      |
| Status stream returns HTTP 503                     | Check that the server is running and fewer than 16 streams are connected. Close unused tabs/readers. Slow streams have bounded writes and are released; each stream stores only the latest diagnostic update.                                                                                                                                                                                                                                                                                                                                                                                  |
| Image build or publish prints a `gitcalver:` error | `local history cannot prove` (exit `4`): incomplete history, usually a shallow clone; fetch full history (`fetch-depth: 0` in CI). `cannot trace` (exit `3`) or `cannot determine default branch` (exit `1`): no shared history with main, or main is not fetched. `committer dates go backwards` (exit `1`): an ancestor has a later UTC date, usually from a wrong clock; do not rewrite main, which reassigns published versions. Commits dated after that day are versioned normally; earlier ones can fail or repeat a published version, which `make release` refuses.                   |
| Release is refused                                 | Inspect the failing required job or immutable-tag error. `Image ... does not match` from `make release` names the staged image and shows its architecture, revision, and version label; a `-dev` suffix on the version label means the image job’s tree was dirty. After a transient registry or network error, re-run the failed jobs; a rerun with identical artifacts is allowed. Otherwise fix the failure and land a new commit; do not replace an existing version tag. Verify both image artifacts came from the same checked workflow run.                                             |

Restarting after a broker or controller outage establishes fresh observations
without outbound write replay. Record reproducible adapter failures with exact
versions, protocol, sanitized numeric DPs, and decoded simulator write counts.
The [hardware acceptance record](hardware-acceptance.md) distinguishes simulated
transport evidence from measured controller behavior.
